SettlementApp & IVR File Format for Data Imports
Please export the CSV file in UTF-8 or ASCII file encoding. Proper escaping must be used (ie, fields containing a quote should be
properly escaped)
Fields R V Notes
unique_id x* An identifier unique *per row*, not per file_number/account.
file_number x This is your identifier for the account. Could be file number, or database ID
file_number_other Alternative ID a user may use to find their record.
balance x Account balance. Must be a decimal without $ signs. IE 100.0, or 200.05
creditor_name x Name of the creditor. You can also send us a separate creditors file.
creditor_id x ID of the creditor. Must be unique to a creditor.
ssn_last_four x* x The last four of the social security number - Please *do not* provide the full SSN.
first_name x x First name of debtor
last_name x x Last name of debtor
full_name x May use this instead of first and last name fields.
dob x Date of birth.
street x Debtor's street
street2 x Debtor's secondary street
city x Debtor's city
state x Debtor's state
zip x Debtor's zip
address x Full Debtor address. May use instead of the above fields.
phone x Debtor's Phone
drivers_license x Debtor's driver's license number
plan_code Your plan code. Can associate plan codes with behavior. HealPay plans get marked with a HealPay plan code
plan_start_date When the plan starts
plan_period Monthly, bimonthly (twice a month), fortnightly (every 2 weeks), weekly, daily
plan_amount Total payment amount of the plan
plan_payment_amount Installment payment amount on the plan
plan_first_payment_amount The first payment owed on the plan
plan_last_payment_amount The last payment owed on the plan
plan_payment_count Number of payments on the plan
interest_rate Rate at which interest accrues. Should be provided as a decimal percent, e.g. 6.00 for 6%
trust_account If there are multiple trust accounts to which payments are routed, must include some identifier per account.
status_code Status codes may be used to handle accounts in particular ways (e.g., offering payment plans or disabling payments)
placement_date Date the account was received
attorney ID for attorney associated with account
treatment Can match the name of a treatment configured in our system to change handling of an account (e.g. hiding balance info)
R - This indicates a required field.
V - This indicates a field that we use to verify the user when they access an account.
* Many CRMs have the ability for merchants to associate multiple entities with the same file number. Some merchants have multiple debtors or consumers for
the same file number, i.e., Person A and Person B are both on the same court case and are paying individual monthly installments against the same case. There
are also merchants that enter the creditor as another row for the same file number. If your system allows for cases like this, we require either a unique row
identifier that will only ever belong to that row (and does not get reassigned if the record gets deleted) or at a minimum the ssn_last_four.
Please filter out unneeded rows when possible. For example, if your system associates the creditor as a second account record row, please filter out the creditor
during export. The exception to this are rows for a debtor that have been updated to indicate a zero balance after having been paid off. We require these to
understand when to clear accounts from our system.
Please filter out critically sensitive information. While we obviously need to have certain types of personally identifying information, things like *full* social
security numbers and credit cards should be redacted.
